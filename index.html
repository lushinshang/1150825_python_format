Python 排版轉換器

貼上 Python 程式碼，用瀏覽器內建的 black 排版並語法高亮顯示。
單一 HTML 檔案，不依賴任何外部網路資源，可在線上使用，也可下載後完全離線使用。

線上開啟使用 下載離線版

下載後雙擊打開 python_format.html 即可離線使用，不需要網路連線、不需要安裝 Python 環境。

為什麼做這個工具

程式碼的排版本來就不該由每個人手動決定——同樣一段邏輯，10 個人可能打出 10 種縮排、引號、換行方式，光是格式不一致就會讓 code review 多花時間在吵「風格」而不是「對錯」。這個工具的目的很單純：貼上去、按一下，拿到一份規則統一、任何人看了都一樣的排版結果，同時不用在自己電腦上安裝 Python 或任何套件，甚至完全不用連網路。

排版的原理

畫面上的「排版」其實是兩件完全獨立的事，先後接力完成：

貼上原始碼 → black 重排結構 → Prism.js 上色

第一步・black（決定「排成什麼樣子」）
black 是 Python 社群最主流的格式化工具，理念是「不妥協」——不提供風格選項，同一份輸入永遠只有一種輸出。運作方式是把程式碼解析成 AST（抽象語法樹），完全丟棄原本的空白與換行，再依固定規則重新印出：行寬 88 字元、字串一律雙引號、縮排 4 格、多行參數自動補尾逗號。也因為是「重印」而非「保留」，就算原本排得很整齊，輸出也可能整段重排。若程式碼本身有語法錯誤，這一步會直接失敗並顯示錯誤訊息，不會硬套格式。

第二步・Prism.js（決定「看起來好不好看」）
black 排好的文字會再交給 Prism.js 做語法高亮：辨識關鍵字、字串、註解、數字等 token，各自包上顏色標記。這一步純粹是視覺呈現，不會改動任何一個字元。

技術上怎麼做到「離線也能跑」

black 原本是要裝在本機 Python 環境才能執行的套件。這個工具透過 Pyodide（WebAssembly 編譯的 CPython）在瀏覽器裡跑一份真正的 Python 直譯器，把 black 與其相依套件的 wheel 檔安裝進這個瀏覽器內的 Python 環境，所以看到的排版結果是瀏覽器裡「真的執行 black」算出來的，不是用 JavaScript 模仿規則。

  • Pyodide 執行環境、black 套件、Prism.js 全部以 base64 編碼直接寫進這份 HTML 檔案裡，不額外連結任何外部檔案。
  • 連瀏覽器原生的 fetch() 都被攔截改寫：Pyodide 初始化時原本會向外部伺服器要資料，這裡改成直接從內嵌的 base64 資料生成回應，讓它「以為」自己連上了網路。
  • 因此不管是連網開啟這個網頁，還是把 python_format.html 下載到完全沒有網路的電腦上雙擊打開，執行的都是同一套流程，結果一致。

使用須知

  • 首次開啟較慢：整個 Python 執行環境（Pyodide）是內嵌在檔案裡直接載入，不用連網下載，但瀏覽器要花幾秒到十幾秒解壓、初始化，畫面上「尚未初始化」變成「就緒」才代表可以格式化。
  • black 只重排格式，不驗證程式邏輯：能排版成功只代表語法正確，不代表程式碼本身沒有 bug；語法有錯會顯示紅色錯誤訊息並保留原輸入，不會讓頁面當掉。
  • 排版規則是固定的：這裡使用 black 的預設規則（行寬 88 字元、雙引號優先等），沒有提供自訂選項——這是 black「不妥協」設計理念的延伸，如果需要不同風格，需要另外用其他工具。
  • 檔案較大（約 19MB）：因為要把整個 Python 執行環境與套件都塞進單一 HTML，下載離線版時請留意網路環境與儲存空間。
  • 資料不會外流：所有格式化過程都在你自己的瀏覽器裡執行，貼上的程式碼不會被送到任何伺服器。

資安檢查報告

用 semgrep（OWASP Top 10 ／ XSS ／ security-audit 規則集）對本專案原始碼做靜態掃描，結果如下：

index.html0 findings
build_assets/template.html（工具實際邏輯原始碼）0 findings
build_assets/build.py（維護用建置腳本）1 項待註記

待註記項目：build.py 裡 urllib.request.urlretrieve(url, path) 被規則標記為「動態網址搭配 urllib 使用」的稽核提醒（因為 urllib 支援 file://，若網址被外部輸入操控，理論上可讀到任意本機檔案）。實際檢查後研判為誤報：這裡的 url 全部來自 build.py 檔案內寫死的下載清單，不接受任何外部或使用者輸入，不構成實際風險。

建置流程的供應鏈驗證：build.py 下載 Pyodide／black／Prism.js 共 18 個檔案時，每個下載完都會核對雜湊值——black 及其相依套件比對 PyPI 官方雜湊，Pyodide 5 個核心檔案的雜湊取自 GitHub Releases 與 jsDelivr CDN 兩個獨立來源交叉比對確認一致，Prism.js 則核對 cdnjs 官方公開的 SRI 值。內容跟預期不符會直接中止建置，避免下載過程被竄改的檔案無聲嵌入 python_format.html。

這層驗證的範圍：只在維護者執行 build.py 建置的當下跑一次，最終產出的 python_format.html 裡不含這段檢查邏輯，使用者開啟工具時不會、也不需要重新驗證。它防的是「下載過程被竄改」，不保證 black／Pyodide／Prism.js 這些上游套件本身沒有漏洞，也不是每次開啟頁面都在跑的即時防護。

下載後自行核對完整性：repo 裡跟 python_format.html 放在一起的 python_format.html.sha256 是每次建置自動產生的 sha256，下載後可以自行核對拿到的檔案有沒有跟 repo 裡的一致。目前這個網頁載入的 python_format.html 對應的 sha256 是：

讀取中…（若一直沒顯示，代表目前不是用 http(s) 開啟這個頁面，瀏覽器基於安全限制擋掉了本機檔案的讀取，改用下方指令自行核對即可）
shasum -a 256 -c python_format.html.sha256

要注意的是，這個雜湊檔案跟 python_format.html 放在同一個 repo、同一個網域發布——如果有人能竄改到這個 GitHub repo 本身，他也能同時改掉雜湊檔，兩者一起被換掉不會被這個核對抓到。這個機制防的是下載損毀或第三方轉貼被動過手腳，不是防 repo 帳號本身被入侵。

結論：本專案程式碼掃描通過，未發現 XSS、注入等可利用漏洞；輸出結果一律以 textContent 寫入畫面（而非 innerHTML），從設計上就避開了最常見的 DOM XSS 風險。
